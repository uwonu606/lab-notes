# lab-notes

새 기술의 작동 방식을 **예측 → 실험 → 설명** 회차로 익힌 기록.

이해했다는 느낌은 재료가 아니다. 남는 건 셋이다 — 돌리기 전에 적은 예측, 실행이 보여 준 상태, 코드를 가리고 쓴 설명.

## 구조

기술 하나가 디렉토리 하나다.

```
asyncio-event-loop/
  notes.md      예측·결과·설명·판정의 기록
  lab/          실험 코드. 상태를 드러내려 돌리는 것이라 지저분해도 된다
```

디렉토리 이름은 기술과 다루는 면을 영문 kebab 2~4 단어로 적는다 — `asyncio-event-loop`, `git-rebase`, `react-rendering`.

## notes.md

| 절 | 언제 쓰나 | 무엇이 들어가나 |
|---|---|---|
| 과제 | 시작할 때 | 이 기술로 당장 하려는 것 한 문장, 거기 필요한 기제 |
| 지도 | 사전 지식을 잰 뒤 | 기제마다 숨은 상태·흔한 오개념·관측할 것·모드 |
| 회차 | 실험마다 | 예측·결과·설명·판정. 번호는 기술 전체로 이어 붙인다 |
| 정리 | 닫을 때 | 처음에 무엇을 어떻게 예측했고 무엇이 고쳐졌는지 |

기제는 문법이나 API 이름이 아니라 "안에서 어떤 상태가 언제 어떻게 바뀌는가"다. 관측할 것이 없는 기제는 실험할 수 없으니 쪼개거나 뺀다.

머리말의 `status` 가 어디까지 왔는지 가리킨다 — `mapping`(지도 그리는 중), `cycling`(회차 도는 중), `done`(과제 시험 통과).

## 쓰는 법

`lab-notes` 스킬이 굴린다. Claude Code 에서 이렇게 부른다.

| 말 | 일어나는 일 |
|---|---|
| "X 익히자" | 같은 기술이 없으면 과제부터 잡고, 있으면 `status` 가 멈춘 자리에서 잇는다 |
| "실험 노트 이어서" | 여기 있는 목록을 보여주고 하나 고르게 한다 |

예측·가설·설명은 사람이 쓴다. 대신 써서 이으면 노트가 제 것이 아니게 된다.

## 저장 위치

스킬은 `LAB_NOTES_HOME` 으로 이 디렉토리를 찾는다. `~/.claude/settings.json`:

```json
{ "env": { "LAB_NOTES_HOME": "/home/ssafy/workspace/alt/lab-notes" } }
```

안 잡으면 `~/lab-notes/` 로 간다.
