## 한 문장

[확인] RIG 는 GPT-3.5 가 session 마다 자유 텍스트 intention 을 쓰게 하고, 같은 split 안에서 **무작위로 짝지은** intention 쌍을 템플릿 문장으로 바꿔 VERA 점수 0.9 초과만 edge 로 남겨 3.4억 edge 를 얻었다. 그래서 intention 사이 edge 는 관찰된 행동이 아니라 plausibility 모델의 상식 판단에서 나온다.

## 지난 틀에서 RIG 의 자리

지난 보고(`03-intention-domain.md`)의 생성기·필터·사람 주석 칸으로 다시 놓는다.

| 칸 | FolkScope | MIND | RIG (코드 기준) |
|---|---|---|---|
| 생성기 | OPT-30B, ConceptNet 관계 prompt | LLaVA-1.5-13b | GPT-3.5 (Azure, temperature 0), 관계 제약 없음 |
| 무엇을 거르나 | 생성된 assertion(노드) | 생성된 intention(노드) | **intention 사이 edge 만**. intention 노드와 concept 는 거르지 않는다 |
| 필터 | DeBERTa classifier | LVLM role-aware filter | fine-tune 한 VERA, 0.9 초과 |
| 사람 주석 | 필터 학습용 | 평가용 | VERA fine-tune 용(전문가 2인) + 평가용(MTurk 5,000건) |

[확인] intention 노드를 거르는 코드는 없다. `generation_result_add_intentions.py:32-45` 는 "intention" 으로 시작하는 줄을 잘라 담기만 한다. 논문도 노드 필터를 설명하지 않는다(`tex:257-259`).

## 2. LLM 의 역할

### GPT-3.5 — intention 생성

[확인] Azure `gpt-35-turbo`, `temperature = 0`, user 메시지 하나다(`data_preprocess/data_preprocess.py:147-155`). prompt 는 다음이다(`:140-142`).

> "Below is a user chronological record list: … Explain the basic intentions of this user exactly. Output several different intentions one by one … intention 1: {a simple verb phrase within 10 words}"

[확인] session 의 마지막 상품(`next_item`)은 prompt 에서 빠진다. 추천 정답 누설을 막는 장치다(`data_preprocess/data_preprocess.py:132-137`).

[확인] 버린 판도 남아 있다. `util.py:64-65` 의 prompt 는 Maslow 욕구 단계까지 붙이게 했다. `prompting.py:81-85` 는 같은 1,000 session 표본을 GPT-4 로 돌렸다. 최종 파이프라인은 GPT-3.5 와 Maslow 없는 prompt 를 쓴다(`tex:687-691`).

### VERA — 관계 필터

[확인] `liujch1998/vera-base`(T5 encoder) 를 불러 연구실 서버의 fine-tune 체크포인트 `/data/jbai/cjf/Vera/vera_best_model.pth` 를 덮어쓴다(`discourse_model/vera_evaluation.py:163-166`). fp16 으로 돌린다(`:168`). 점수는 마지막 토큰 hidden 에 VERA 고유 linear head 와 temperature 보정을 씌운 sigmoid 다(`:170-177`, `:240-248`).

[확인] 후보 쌍은 **무작위**다. split 하나의 intention 목록 전체를 head 로 돈다. head 마다 같은 split 에서 100개 tail 을 뽑는 일을 5번 한다. 각 쌍을 관계 3가지로 문장화한다(`:159-160`, `:181-191`, `:215-232`).

[확인] 그래서 intention-intention edge 는 같은 split(10만 session 무작위 묶음) 안에서만 생긴다. session 공출현이나 embedding 유사도로 후보를 좁히지 않는다. `answer_process.py:102-131` 의 mpnet 유사도 코드는 이 경로에 쓰이지 않는다.

[추정] 판정한 문장 수는 약 77억 개, 통과율은 약 4.4% 다. 근거: head 하나당 5 × 100 × 3 = 1,500 문장이다. head 수는 session-intention edge 5,115,587(`tex:200`) 과 같다고 보았다. 341.6M ÷ 7.7B ≈ 4.4% 다. 스크립트는 `Pass rate` 를 출력하지만(`:258-260`) 그 로그는 저장소에 없다.

### Llama-3-8B-Instruct — 개념화

[확인] `Meta-Llama-3-8B-Instruct` 를 bf16, `do_sample=True, temperature=0.6, top_p=0.9` 로 돌린다(`abstract_generate.py:84-88`, `:49-53`). intention 하나에 1–3단어 구 여러 개를 쉼표로 받는다. few-shot 2개와 세 조건(대표성·모호하지 않음·서로 겹치지 않음)을 준다(`:12-24`). 출력은 쉼표로 자르고 strip 만 한다(`:57-58`). 정규화·중복 병합은 없다.

[확인] GPT-3.5 로 같은 일을 시험한 판이 있다(`abstract_generate_api.py`). 그 표본에서 두 번 이상 나온 concept 비율은 29.3%, concept 집합이 겹치는 intention 쌍 비율은 1.8% 였다고 주석에 적혀 있다(`abstract_generate_api.py:106-107`).

## 3. Schema

### 관계는 코드상 3종이다

[확인] 논문은 "five relationship types: precedence, succession, simultaneity, cause, and result" 라고 쓴다(`tex:289`). 템플릿 함수는 5종을 다 갖는다(`discourse_model/vera_evaluation.py:45-58`).

| 관계 | 템플릿 |
|---|---|
| succession | "People {A} usually after they {B}." |
| precedence | "People {A} usually before they {B}." |
| reason | "People {A} mainly because they {B}." |
| result | "People {A}, and as a result, they {B}." |
| synchronous | "People {A}, and simultaneously, they {B}." |

[확인] 하지만 그래프를 만드는 루프는 `['succession', 'reason', 'synchronous']` 셋만 돈다(`discourse_model/vera_evaluation.py:227`). 집계 스크립트도 세 템플릿 문구만 센다(`intention_relations_count.py:13-21`). 논문 표도 Asynchronous 100.2M / Synchronous 112.6M / Causality 128.7M 세 묶음이다(`tex:356-358`, `tex:188`).

[추정] precedence 와 result 는 succession·reason 의 역방향으로 셈해진 것으로 보인다. 근거: 무작위 쌍을 양방향으로 다 뽑으므로 (A after B) 와 (B before A) 는 같은 판정이다. 이를 밝힌 문장은 논문과 코드 어디에도 없다.

### 관계를 정한 근거

[확인] 논문은 Penn Discourse Treebank 2.0 주석 지침을 따랐다고 쓴다(`tex:290`). temporal(before/after), synchronous, causality 는 PDTB 의 Temporal·Contingency 계열이다.

[추정] 같은 연구실 ASER 의 discourse 관계 체계를 줄여 쓴 것이다 — 사례 1개: 집계 스크립트가 causal 을 "contingency" 라고 부른다(`intention_relations_count.py:8`, `annotation/post_processing_scripts/intention_relations.py:15`).

[확인] 관계 수를 왜 3(또는 5)으로 정했는지에 대한 실험·근거는 없다.

### 노드는 자유 텍스트다

[확인] 노드 유형은 product, session, intention, concept 넷이다(`tex:184`).

| 노드 | 형태 | 정규화 |
|---|---|---|
| session | 상품 ID 목록 | 없음 |
| intention | 10단어 이내 동사구, 자유 텍스트 | 없음. dict key 로 쓰여 문자열이 같을 때만 합쳐진다(`generation_result_compute_intention_embedding.py:134-136`) |
| concept | 1–3단어 구, 자유 텍스트 | strip 만 |

[확인] ConceptNet 관계 제약을 뺀 것은 의도된 선택이다. 제약을 다시 넣으면 plausibility 0.9542, typicality 0.6430 으로 떨어진다(`tex:322-323`). n-gram 다양성은 FolkScope 보다 높다(`tex:670-674`, 표본 1,700개). 저장소의 전체 코퍼스 계산은 2-gram 비율 0.057 대 FolkScope 0.016 이다(`uniq_n_gram_counting.csv:2`). 논문 표의 0.5274 는 표본 기준이라 값이 크다.

## 4. 품질 관리

### 필터 임계값

| 대상 | 임계값 | 근거 |
|---|---|---|
| intention 노드 | 없음 | #지난 틀에서 RIG 의 자리 |
| intention-intention edge | VERA > 0.9 | `discourse_model/vera_evaluation.py:154`, `:253` |
| concept | 없음 | `abstract_generate.py:57-58` |

[확인] 임계값 민감도 표는 0.85 → 412.0M edge·수용률 79.8%, 0.90 → 341.6M·81.2%, 0.95 → 218.0M·82.4% 다(`tex:938-940`). 저장소의 관계 주석 batch 는 하나뿐이다. 그래서 0.85·0.95 의 수용률은 저장소 데이터로 다시 계산할 수 없다.

### VERA fine-tune

[확인] fine-tune 전후 F1 은 0.74 → 0.89 다(`tex:267-268`). 학습 데이터는 전문가 2인이 주석했고 초기 일치율은 85% 다(`tex:290`).

[확인] 학습 데이터의 구성은 논문 본문에서 지워졌다. 주석 처리된 문단에만 남아 있다. 양성 1,000개와 무작위 음성 1,000개, 학습 1,600 / 검증·시험 200 이다(`tex:285`).

[확인] fine-tune 코드, 학습 CSV(`positive_samples_new.csv`, `negative_samples_random_label.csv`), 체크포인트는 저장소에 없다. 원본 VERA 를 평가한 기록만 있다. threshold 0.4 에서 "Vera T5" F1 0.778, "Vera Base" F1 0.761 이다(`discourse_model/vera_scoring.py:207-226`).

### 사람 검수 — 재현함

[확인] `annotation/annotation_raw/` 의 MTurk 원자료 3개를 직접 다시 계산했다(`sources/03-rig/tools/reproduce_annotation.py`). 논문 수치가 그대로 나왔다(`sources/03-rig/outputs/annotation_reproduction.txt`).

| 대상 | 표본 | 판정자 | 재현값 | 논문 |
|---|---|---|---|---|
| session-intention | 3,000 쌍 × 3표 | 237명 | plausibility 0.9552, typicality 0.6674, 일치 0.91 | 0.9552 / 0.6674 / 0.91 (`tex:322`, `tex:334`) |
| intention-concept | 1,000 쌍 × 3표 | 108명 | 정답률 0.8660, 일치 0.772 | 86.60% / 77.19% (`tex:375`) |
| intention-relation | 1,000 쌍 × 3표 | 103명 | 수용률 0.8123 (reason 0.804, succession 0.806, synchronous 0.828), 일치 0.686 | 81.2 / 80.4 / 80.6 / 82.8, 0.69 (`tex:355-358`, `tex:368`) |

[확인] 읽을 때 걸러 들을 점이 넷 있다.

- 수치는 다수결이 아니라 **표 전체 평균**이다. 다수결로 세면 plausibility 0.996, concept 0.946, relation 0.916 으로 더 높다.
- "inter-annotator agreement" 는 kappa 가 아니라 단순 쌍별 일치율이다. 스크립트가 행 순서로 `counter % 3` 을 판정자 번호로 쓴다(`annotation/post_processing_scripts/intention_relations.py:30`).
- typicality 는 4지선다를 1 / 0.5 / 0 / −1 로 바꾼 평균이다(`annotation/post_processing_scripts/session_intention_annotation.py:29-52`).
- 표본이 그래프 전체에서 고르게 뽑히지 않았다. session-intention 은 split 5 에서 intention 이 4개 이상인 session 의 **앞 3개** intention 이다(`annotation/session_intention_sampling.py:15-17`, `:70`, `:90`). relation 은 split 2 의 통과 행 중 **앞 20,000행**에서 1,000개를 뽑았다(`annotation/intention_relation_sampling.py:14`, `:43-49`). concept 는 intention 하나의 concept 집합 전체를 한 번에 판정한다(`annotation/intention_conceptualization_sampling.py:19`).

## 5. 저장·질의 — 추천 모델에 붙이는 법

### 논문의 설명

[확인] 3.5억 edge 를 추천에 직접 넣지 않는다. meta-path 로 session 쌍을 고른다(`tex:513`). 조건은 둘 중 하나다.

- commonsense 관계 노드를 지나는 서로 다른 meta-path 가 6개 이상이다.
- 한 session 의 모든 concept 노드에서 다른 session 에 닿는다.

[확인] 고른 session 쌍 안의 상품 공출현 수를 가중치로 하는 item graph 를 만든다(`tex:514`). 그 위에 LightGCN 식 convolution(sum pooling)으로 item embedding 을 만들고 SASRec 으로 session 을 인코딩한다(`tex:521-523`).

### 저장소에 있는 것

[확인] GCN 모듈은 있다. 2층 sparse 곱, layer 출력 합산, 학습 때 edge dropout 0.2 다(`rec_model/modules.py:201-222`). item graph 로 보이는 `rec_model/mat_m2_seqf.npz` 도 있다.

[확인] 그 행렬을 직접 열어 보았다(`sources/03-rig/outputs/rec_data_inspection.txt`). 494,409 × 494,409 대칭 행렬이다. 0 아닌 값 4,511,775개, 값은 2–1,735 의 정수다. 상품 수는 `rec_model/data/m2.txt` 의 494,409 와 같다.

[확인] 하지만 KG 에서 이 행렬을 만드는 meta-path 코드는 저장소에 없다. `meta`, `save_npz`, `coo_matrix` 를 찾아도 생성 코드가 나오지 않는다. [추정] 이 행렬이 KG 유래인지 단순 공출현인지 저장소만으로는 가릴 수 없다 — 근거: 파일 이름 `seqf` 와 최소값 2 는 공출현 빈도에 문턱을 둔 모양과도 맞는다.

### 공개된 추천 코드는 그대로 돌지 않는다

[확인] 읽어서 확인했다. GPU 가 없어 실행은 못 했다.

- `rec_model/main.py:88` 이 `trans_mat_norm = None` 으로 둔 뒤 `:99` 에서 `trans_mat_norm[0]` 을 읽는다. TypeError 다.
- `rec_model/main.py:102` 는 그래프를 `mat = 1` 로 덮는다.
- `rec_model/model.py:49-59`, `:69-70` 에서 GCN 호출이 주석 처리돼 있다. 그런데 `rec_model/trainer.py:78`, `:100`, `:119` 는 `get_gcn_embedding()` 을 부른다. AttributeError 다.
- README 가 말한 `mat_m2.npz` 는 저장소에 없다.
