앞선 트랙의 `../llm-wiki-implementations/my-thinking.md`는 9개 구현 비교에서 나온 결정 D1~D12의 입장을 쌓는 파일이고, 이 파일은 네 레포와 엔터프라이즈 조건에서 나온 결정 E1~E22의 입장을 쌓는다.

E 결정 가운데 D와 겹치는 것(`curriculum.md` #앞 트랙 결정이 간 자리)은 입장을 정할 때 앞선 파일 #생각 기록에 "네 레포 트랙 E2 입장(날짜) — D2에 닿음"과 내 말 인용을 덧붙인다. D 행은 내가 그 트랙에서 직접 답할 때만 고친다. 두 파일이 어긋나면 늦은 날짜의 근거로 다른 쪽을 다시 연다.

이 파일은 내 생각만 담는다.
Claude는 내가 한 말을 큰따옴표로 옮겨 적는다.
Claude가 내 말을 요약하거나 대신 써 넣지 않는다.
새 세션은 이 파일을 끝까지 읽고 시작한다.

## 설계 한 장

10단원 끝, 11단원 직전에 채운다.
지금 입장 22줄을 하나의 설계로 묶는 자리다. 11단원은 이 절대로 뼈대를 만든다.

들어갈 것은 다섯이다.

| 들어갈 것 | 무엇을 적나 |
|---|---|
| 디렉터리 구조 | 원문, 사실 장부, 용어집, 판정 기록, 조각 색인, 페이지 투영, 대기열이 어디에 놓이는가 |
| 한 바퀴 순서 | ingest → 같은 대상 판정 → 장부 → 연결 후보 → 발행 → 질의가 도는 순서와, 단계마다 LLM과 코드 가운데 누가 하는가 |
| 쓰기 경로 목록 | 디스크에 쓰는 모든 경로와, 그 경로가 지나는 쓰기 함수 하나 |
| 사람이 개입하는 자리 | 어느 대기열에서 무엇을 승인하고, 승인자가 어디에 남는가 |
| 부딪힘 대조 | `00-comparison.md` #어울리는 조합과 부딪히는 조합 표와 내 입장 조합을 한 줄씩 대조한 결과 |

```markdown
### YYYY-MM-DD · 단원 N · E번호
- 물음: 후보를 넓게 잡고 판정에서 거를 것인가, 좁게 잡을 것인가?
- 내 말: "…"
- 바뀐 입장: E7 미정 → … (바뀐 게 없으면 이 줄을 뺀다)
- 다시 연 결정: E5 — 이유 … (없으면 이 줄을 뺀다)
```
